# Ticketing

A ticket is issued in the registration transaction and exported only from persisted records. One ticket contains the full three-member roster. Pending-review tickets are clearly labeled and cannot be checked in. All formats use the same public registration ID and deterministic cryptographic verification token.

All visible SVG text is rendered as glyph outlines from bundled Yatra One and DejaVu fonts, with escaped accessible titles/labels; preview and rasterization no longer depend on browser/system font substitution. QR includes only APP_ORIGIN/verify/<token>. The URL token is HMAC-SHA256 over a random UUID using TOKEN_SECRET; only its SHA-256 lookup hash is stored. The server can reproduce it for exports without storing plaintext. Protect the master secret; rotating it requires reissuing ticket hashes and retrieval cookies.

The shared ticket canvas is 1200×720 (`TICKET_SIZE` in `lib/tickets.ts`); confirmation markup declares this ratio to avoid layout shifts. Sharp rasterizes SVG at density 192 (3200×1920 pixels). The poster portion is raster, not vector PDF text; it remains high-resolution at the intended print size. QR is standards-compliant, error-correction M with a quiet margin. Download generation is throttled and private/no-store.

Public scans only inspect state. They never write a check-in. Verified organizers paste a scanned URL/token into the dashboard, verify, and explicitly confirm admission. Revocation overrides checked-in display status. No PII contacts appear on the ticket or public verification.
